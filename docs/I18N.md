# Локализация

Первый словарь — `locales/uk.json`. Украинский остаётся языком приложения.
Вынесены статические тексты интерфейса, ошибки API, SEO, письмо восстановления,
демонстрационные данные и справочники. Пользовательские вакансии и резюме не переводятся.

```js
import { translate } from '../i18n/index.js';
translate('navigation.employers');
translate('auth.recovery.emailBody', { resetUrl });
```

Ключи плоские, сгруппированы по области. Основные ключи имеют семантические имена
(`auth.login`, `jobs.add`); остальные извлечённые ключи используют транслитерацию
исходного текста с префиксом модуля. Ключ — стабильный идентификатор: изменение
формулировки в словаре не требует переименования ключа в компонентах.

## Добавление локали

1. Создать `locales/<locale>.json` с теми же ключами, переведя значения.
2. Импортировать словарь и добавить его в `dictionaries` в `i18n/index.js`.
3. Добавить формат локали в `formatLocales` в `i18n/config.js`.
4. Для перевода явно выбранной локали использовать `createTranslator(locale)`.
   Независимые переводчики безопасны при одновременном использовании.
5. Для смены языка всего приложения изменить `defaultLocale` и пересобрать приложение.
   URL с локалью, выбор языка пользователем и сохранение этого выбора пока не добавлены.

Отсутствующий перевод берётся из украинского словаря. Неизвестный ключ или
пропущенный параметр вызывает ошибку, чтобы проблема не оставалась незаметной.
Параметры — `{name}`; строки возвращаются как обычный текст. React экранирует их
при выводе; не использовать переводы с `dangerouslySetInnerHTML`.

## Данные и подписи

`catalogValue(key)` возвращает каноническое украинское значение существующей базы:
города, профессии, графики, формат работы, опыт и ключи дополнительных полей.
Не переводить значения, отправляемые в API, и не менять канонические значения
без миграции базы. Для новых перечислений следует вводить языконезависимые ID.
`catalogLabel(value, locale)` предназначен для подписи канонического значения.
Поисковые синонимы и нормализация остаются ориентированными на украинские данные.
Расширение географии и языков поиска — отдельное изменение.

`formatNumber` и `formatDate` централизуют форматирование чисел и дат.
`html.lang` и подписи CSS для печати используют конфигурацию и словарь.
Технические сообщения для логов, регулярные выражения поиска, URL и SQL не являются
пользовательскими переводами.

## Проверки

`npm test` проверяет ключи, параметры, fallback, независимость переводчиков и
отсутствие кириллических текстовых литералов в исходниках приложения.
`npm run build` и `npm run test:http` проверяют сборку и действующие сценарии.
