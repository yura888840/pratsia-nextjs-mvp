# Праця — восстановленный проект Next.js

Восстановлено из `www_6_11_2026.zip` 6 ноября 2026 года. Это редактируемая реконструкция на JavaScript/JSX, а не точная копия утраченного TypeScript-репозитория. В архиве не было source maps.

## Запуск

Нужен Node.js >= 22.16 (проверено на 24.22.1).

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Для production:

```bash
npm run build
npm start
```

SQLite создаётся автоматически в `data/pratsia.sqlite`; миграции повторяемы. Реальной базы пользователей и вакансий в исходном архиве не было, поэтому первый запуск создаёт пустую базу. Демо-справочники и интерфейс сохранены, реальные вакансии можно создать через приложение.

`PRATSIA_ORIGIN` должен точно совпадать с адресом в браузере, включая порт. Если используете `127.0.0.1`, замените `localhost` в настройке. Для переноса существующей базы остановите сервер, сохраните резервную копию и используйте существующий каталог данных; тестовую базу из этой работы архив не содержит.

Для единого нестандартного пути БД экспортируйте абсолютный `PRATSIA_DATA_DIR` в окружение перед запуском команд: отдельные CLI-скрипты не загружают `.env.local`, а Next.js загружает. Значение по умолчанию `./data` одинаково для обоих.

## Проверки

```bash
npm test
```

Проверяет повторный запуск миграций, пароли, одноразовое восстановление пароля и отзыв старых сессий.

Для HTTP-проверок запустите приложение на отдельной тестовой базе:

```bash
# Терминал 1; используйте пустой временный каталог.
PRATSIA_DATA_DIR=/tmp/pratsia-http-test PRATSIA_MAIL_DISABLED=1 npm start -- --hostname 127.0.0.1 --port 3101
# Терминал 2
npm run test:http
```

При заданном `.env.local` укажите для этого сервера `PRATSIA_ORIGIN=http://127.0.0.1:3101`. HTTP-тест создаёт два тестовых аккаунта и вакансии, поэтому запускается только для localhost/127.0.0.1. Не направляйте его на рабочую БД. После теста остановите сервер и удалите временную тестовую базу.

Результат восстановления: production-сборка прошла; 21 HTTP-проверка прошла; тест миграций/смены пароля прошёл. Полное визуальное сравнение и браузерные клики не проверены: Chromium не удалось установить в среде восстановления. Доставка email не проверялась; при тестировании отправка отключена.

## Почта и модерация

По умолчанию в примере окружения `PRATSIA_MAIL_DISABLED=1`. Для реальной отправки нужен настроенный sendmail на сервере, `PRATSIA_MAIL_DISABLED=0`, адрес отправителя и HTTPS origin. Исходная логика восстановления требует HTTPS-ссылку для письма.

```bash
npm run moderator -- grant verified-account@example.com
npm run moderator -- revoke verified-account@example.com
npm run db:backup
```

Скрипт назначения модератора требует существующий аккаунт с подтверждённой почтой; в восстановленном коде подтверждение происходит при успешном завершении восстановления пароля. Эта логика сохранена из билда.

## Что восстановить точно невозможно

- Исходные TypeScript-типы, интерфейсы, комментарии и первоначальные имена большинства локальных переменных.
- Файлы, исключённые компилятором: исходные тесты, README, CI/CD, git-история, неиспользуемый код.
- Реальные данные SQLite, окружение хостинга, почтовые настройки и секреты.
- Точные версии встроенных Drizzle/Zod/Lucide: сохранён код из сборки, а не подобраны новые версии библиотек.

Оригинальные пути `app/platform.tsx`, `app/layout.tsx` и маршрутов видны в build manifests. Новое разделение `lib/` и `db/`, часть имён функций, package.json, конфигурация, тесты и этот README восстановлены/созданы при работе. Некоторые локальные имена и export-алиасы в vendor остаются короткими. Основной интерфейс был большим модулем и остаётся таким: дальнейшая декомпозиция возможна отдельно.

Next.js 16.3.4 и React/React DOM 19.2.6 подтверждены пакетами архива. `package-lock.json` создан заново при проверке установки. Сайт pratsia.com.ua при чтении отдавал те же имена CSS/JS-чанков, что и переданный архив. Внешний сайт не изменялся.

`recovery-manifest.json` связывает восстановленные файлы с модулями сборки. Для standalone-развёртывания можно собрать с `PRATSIA_STANDALONE=1`; тогда нужно отдельно подготовить `.next/static`, `public`, `drizzle` и абсолютный путь БД рядом с standalone-сервером. Обычные `npm run build` / `npm start` уже работают без этого режима.
